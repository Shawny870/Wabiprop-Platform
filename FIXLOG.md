- F38 — **PR 1: room availability integrity — the guest-facing double-booking race, plus the fail-open read behind it.** Surfaced by a full-repo fault audit (three independent passes, reconciled), not by a device report — the highest-severity finding on that list: guest-facing, highest-traffic, predates every feature built this session. **P1a: no re-check after the room is held, on either guest path.** `collectDetails` (overnight) calls `findAvailableRoom` once, then `airtableCreate`s the hold with zero re-verification — neither `selectOccupancy` nor `recordEta` re-checks either, all the way to `Confirmed`. `selectHourlyDuration` (hourly) is worse: it writes `Status: 'Confirmed'` directly in one call, no intermediate `Enquiry` state, no re-check anywhere. `walkinBooking` is the only creation path with a post-write rollback — because it was built for one reception handset.
